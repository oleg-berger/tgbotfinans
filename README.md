# Telegram-бот для учета финансов

Личный учет в тенге прямо в Telegram: банки, доходы и расходы, переводы, статистика, ожидаемый и выплаченный кэшбэк. Доступ — только по списку Telegram ID. У каждого пользователя отдельные данные. Веб-интерфейса и подключения к банковским счетам нет.

## Запуск в Windows

Нужен Python 3.12 и доступ к Telegram API. Откройте PowerShell в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Создайте бота через **@BotFather** в Telegram (`/newbot`) и внесите его токен в `BOT_TOKEN`. В `ALLOWED_USER_IDS` укажите числовые ID владельца и приглашенных через запятую. Пустой список запрещен. Узнать ID можно у бота, показывающего Telegram ID; уже запущенный этот бот также сообщает ID пользователю, которому доступ закрыт. Не пересылайте токен в чат и не публикуйте `.env`.

```dotenv
BOT_TOKEN=ваш_токен_от_BotFather
ALLOWED_USER_IDS=123456789,987654321
DATABASE_PATH=data/finance.sqlite3
BACKUP_DIR=backups
```

Проверка конфигурации и запуск:

```powershell
.\.venv\Scripts\python.exe -m financebot --check
.\.venv\Scripts\python.exe -m financebot
```

Либо запустите `start.ps1` из PowerShell. `--check` не подключается к Telegram и не проверяет действительность токена. Бот работает, пока процесс запущен и компьютер не спит. Остановка — `Ctrl+C`. После изменения списка доступа перезапустите процесс.

В личном чате отправьте `/start`: бот поприветствует вас и предложит пройти короткий гайд на 7 страниц. Переключайтесь кнопками «Далее» и «Назад». На последней странице нажмите «Создать категории», выберите расход или доход, введите название и ключи. После сохранения категории откроется главное меню. Остальные категории можно добавить в разделе «Категории»; первый банк, его ключи, текущий остаток и банк по умолчанию — в разделе «Банки».

Повторный `/start` снова показывает приветствие, сохраняя ваши банки, категории и операции. Гайд также доступен через Настройки → Помощь. Команды `/menu`, `/cancel`, `/help` всегда доступны. Группы игнорируются. Данные, страница гайда и незавершенные диалоги сохраняются после перезапуска. Пока гайд текстовый; фотографии будут добавлены отдельно.

## Как пользоваться

1. **Категории → Расходы → Добавить**: создайте «Продукты», ключи `пр, еда`.
2. **Банки → БЦЦ**: задайте ключи банка. Название банка тоже работает как ключ.
3. **Кэшбэк → месяц → БЦЦ → Настроить категорию**: выберите «Продукты», введите `3` и решите, пересчитывать ли старые покупки.
4. Отправьте `250 пр бцц`. Списание — 250 ₸, ожидаемый кэшбэк — 7,50 ₸. До фактической выплаты кэшбэк не входит в остаток.

Другие примеры:

```text
250
```

Расход в «Прочее», банк по умолчанию. Если основной банк не выбран, бот попросит выбрать его.

```text
15000 зп
```

Доход, если `зп` привязан к категории доходов. Знаки `+` и `−` для обычных записей не нужны и не принимаются.

```text
250,50 пр бцц
04.09.2026
```

Запись задним числом. Будущие даты не принимаются. Сумма — без разделителя тысяч, до двух знаков после запятой. Ключи регистронезависимы, задаются через запятую; названия с пробелами поддерживаются. Неизвестное слово предлагает привязать его к банку/категории или создать новый объект. До завершения выбора расход не сохраняется.

**Бюджет** — сумма текущих остатков всех банков, включая архивные. Начальные остатки, корректировки и переводы исключены из доходов и расходов статистики. Начальный остаток записывается датой создания банка; операции задним числом также влияют на сегодняшний баланс.

**Переводы и сверка** находятся в карточке банка. Сверка записывает разницу между введенным остатком и текущим расчетом. Последующее изменение старых операций меняет расчетный остаток; при необходимости выполните сверку снова. Минусовой остаток разрешен.

**Операции** позволяют изменять сумму и дату. У обычных доходов/расходов также меняются банк и категория. Изменение категории может поменять доход на расход. У переводов банк назначения меняется удалением перевода и созданием нового. У начального остатка/корректировки редактируется именно сумма записи (разница для корректировки). Удаление требует подтверждения.

**Кэшбэк** настраивается отдельно для календарного месяца, банка и категории расходов. Изменение суммы покупки сохраняет ее прежнюю ставку; изменение банка, категории или месяца берет актуальную ставку нового сочетания. Изменение ставок и копирование из прошлого месяца всегда спрашивают, пересчитывать ли имеющиеся покупки. Ноль означает настроенные 0%; отсутствие ставки — «не настроен».

**Выплата кэшбэка**: выберите банк и месяц покупок, подтвердите фактически полученные сумму и дату. Создается отдельный доход. На банк и месяц допускается одна подтвержденная выплата; при нескольких частях выплаты увеличивайте ее сумму до общего полученного значения. Кнопка «Изменить выплату» открывает связанную операцию. Ее удаление позволяет подтвердить выплату снова. Изменение покупок не изменяет уже полученный доход.

Первого числа в **09:00 по часовому поясу пользователя** приходит напоминание. Часовой пояс по умолчанию — `Asia/Qyzylorda`, меняется в настройках. Если бот не работал, после запуска отправляется только пропущенное напоминание текущего месяца. Ставки сами не переносятся. При редком сбое строго между отправкой напоминания в Telegram и отметкой доставки возможно повторное уведомление; финансовые записи защищены отдельной транзакционной дедупликацией.

**CSV**: Статистика → нужный месяц → CSV. UTF-8 с BOM, разделитель `;`, суммы с десятичной запятой. Включены переводы, корректировки, ожидаемый кэшбэк и месяц выплаты. Архивирование банков/категорий сохраняет историю, освобождает ключи и убирает объект из нового ввода. Архивный банк продолжает участвовать в балансе.

## Резервные копии и восстановление

### Сброс только одного пользователя

Узнайте Telegram ID в разделе «Настройки», затем остановите бота (`Ctrl+C`). В PowerShell из папки проекта сначала проверьте выбранный ID и количество записей:

```powershell
.\.venv\Scripts\python.exe -m financebot.reset_user 123456789
```

Замените `123456789` на свой ID. Это предварительный просмотр, он ничего не удаляет. Если ID и путь базы верны, выполните сброс:

```powershell
.\.venv\Scripts\python.exe -m financebot.reset_user 123456789 --confirm
```

Удаляются операции, банки, категории, ставки и выплаты кэшбэка, настройки, диалоги и история напоминаний только выбранного пользователя. Данные других пользователей и список доступа в `.env` сохраняются. Перед удалением создается полная согласованная копия базы `before-reset-…sqlite3` в `BACKUP_DIR`; при ошибке копирования удаление не начинается. Эти копии не удаляются ежедневной ротацией и содержат также данные других пользователей.

Очистите старую переписку с ботом на телефоне, чтобы не использовать старые кнопки, затем запустите бота обычной командой и отправьте `/start`. После сброса появятся стандартные категории «Прочее» и «Кэшбэк», остальные настройки выполняются заново. Сбрасывается база, выбранная в текущем `.env`: если ранее переключались на новую базу, сначала проверьте `DATABASE_PATH`. Старые резервные копии и ранее экспортированные CSV остаются.

### Автоматические копии

При первом цикле обслуживания каждого UTC-дня создается согласованная копия SQLite в `backups/finance-ГГГГ-ММ-ДД.sqlite3`. Используется SQLite Backup API, затем `integrity_check`; остаются последние семь копий. Бот проверяет задания раз в минуту. Копии содержат финансовые данные: ограничьте доступ к каталогу и отдельно сохраняйте копии на другом диске. Копия на том же диске не защищает от поломки диска.

Для восстановления:

1. Остановите бота. Убедитесь, что второго процесса нет.
2. Сохраните текущую папку `data` отдельно, включая возможные файлы `-wal`/`-shm`.
3. Создайте **новую пустую папку**, например `data-restored`, скопируйте туда выбранную резервную копию под именем `finance.sqlite3`.
4. Укажите `DATABASE_PATH=data-restored/finance.sqlite3` в `.env`. Не переносите старые `-wal`/`-shm` в новую папку.
5. Запустите бота и проверьте баланс и последние операции. При восстановлении старой копии записи после ее создания отсутствуют.

Для немедленной копии при переносе остановите бота и выполните SQLite backup из Python:

```powershell
.\.venv\Scripts\python.exe -c "import sqlite3; from contextlib import closing; from pathlib import Path; Path('transfer').mkdir(exist_ok=True); src=sqlite3.connect('data/finance.sqlite3'); dst=sqlite3.connect('transfer/finance.sqlite3'); src.backup(dst); dst.close(); src.close()"
```

Если меняли `DATABASE_PATH`, подставьте свой путь. Переносить нужно эту согласованную копию, а не только основной файл работающей WAL-базы.

## Перенос на Linux

Используйте сервер с Python 3.12. Перенесите исходники и файлы зависимостей в `/opt/tgbotfinans`; Windows-каталог `.venv` не переносите. Подготовьте пользователя и окружение:

```bash
sudo useradd --system --home /opt/tgbotfinans --shell /usr/sbin/nologin financebot
sudo mkdir -p /opt/tgbotfinans/data /opt/tgbotfinans/backups
sudo chown -R financebot:financebot /opt/tgbotfinans
sudo -u financebot python3.12 -m venv /opt/tgbotfinans/.venv
sudo -u financebot /opt/tgbotfinans/.venv/bin/python -m pip install -r /opt/tgbotfinans/requirements.txt
```

Остановите Windows-бота. Поместите согласованную копию базы в `/opt/tgbotfinans/data/finance.sqlite3`, создайте `.env` с тем же токеном и списком доступа; пути оставьте `data/finance.sqlite3` и `backups`. Установите владельца `financebot:financebot` для базы и `.env`, права `.env` — `600`.

```bash
sudo cp /opt/tgbotfinans/deploy/financebot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now financebot
sudo systemctl status financebot
sudo journalctl -u financebot -n 50
```

Для нестандартных путей базы/копий обновите `ReadWritePaths` в service-файле. Входящий HTTP-порт не нужен: используется long polling. Одновременно должен работать один экземпляр с этим токеном. Локальная блокировка защищает от двух процессов с одной базой; она не защищает от запуска того же токена на другом компьютере.

Обновления: остановить сервис, сделать копию, обновить исходники и зависимости, запустить. Версионированные миграции применяются при старте; более новая неизвестная версия базы отклоняется. В логах приложения выводятся только типы ошибок, без токена и текстов финансовых сообщений.

## Проверки и структура

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q financebot
```

`parsing.py` — ввод и точная арифметика; `ledger.py` — финансовые правила; `database.py` — миграции/транзакции; `application.py` — доступ и дедупликация; `dialogs.py` и `views.py` — Telegram-сценарии; `runtime.py` — aiogram; `jobs.py` — напоминания и копии. Обработка события, изменение диалога и сохранение ответа коммитятся вместе. Старые кнопки подтверждения защищены одноразовым идентификатором диалога.

Ручная приемка с тестовым ботом: `/start` → приветствие → 7 страниц гайда → «Создать категории» → категория расходов «Продукты» и ключ `пр` → главное меню → банк с 10 000 ₸ → кэшбэк 3% → записать `250 пр` → проверить 9 750 ₸ и 7,50 ₸ → подтвердить выплату → создать второй банк → перевести 100 ₸ → изменить расход → выгрузить CSV → перезапустить и проверить сохранность. Автоматические тесты не заменяют проверку настоящего токена и соединения с Telegram.

## Запуск в Docker

Нужен Docker с Linux-контейнерами (на Windows — Docker Desktop).
Используется существующий `.env`; если его нет, скопируйте `.env.example`
и заполните `BOT_TOKEN` и `ALLOWED_USER_IDS`.

Сборка образа и проверка конфигурации без подключения к Telegram:

```bash
docker compose build
docker compose run --rm financebot python -m financebot --check
```

Перед запуском остановите экземпляр бота, запущенный через Python или systemd
с тем же токеном. Затем:

```bash
docker compose up -d
docker compose logs -f --tail=100 financebot
```

База `data/finance.sqlite3` и резервные копии в `backups/` сохраняются на хосте
при пересоздании контейнера. Пути `DATABASE_PATH` и `BACKUP_DIR` из `.env`
в Compose переопределены на `/app/data/finance.sqlite3` и `/app/backups`.
Если ваша база находится в другой папке или имеет другое имя, измените
соответствующий bind mount и `DATABASE_PATH` в `compose.yaml` перед запуском.
Секреты, база и резервные копии не включаются в образ.

Контейнер работает от пользователя с UID/GID `10001`. На Linux предоставьте
ему права на папки данных перед первым запуском:

```bash
sudo mkdir -p data backups
sudo chown -R 10001:10001 data backups
```

Остановка и обновление:

```bash
docker compose down
docker compose up -d --build
```

HTTP-порты не требуются: бот использует long polling. Политика
`unless-stopped` перезапускает контейнер после сбоя и перезапуска Docker;
Docker Desktop должен быть запущен.
